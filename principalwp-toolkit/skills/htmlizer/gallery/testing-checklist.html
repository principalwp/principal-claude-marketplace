Step 1

Add the backpack to a fresh cart

Action

Add 1 unit of the Trailrunner Backpack (sku_2291) to a new cart via the API.

# add 1x Trailrunner Backpack (sku_2291) to a fresh cart
curl -X POST https://api.northwind-shop.com/v1/cart/add \
  -H "Content-Type: application/json" \
  -d '{"product_id": "sku_2291", "qty": 1}'
Pass

201 with a cart_id and one line item at qty: 1.

Watch

Adding the same SKU a second time should merge into the existing line item (qty: 2), not create a second line — a duplicate line is the most common cart bug here.

Step 2

Apply a valid promo code

Action

Apply the promo code SUMMER10 to the cart from step 1.

# promo codes are case-insensitive; SUMMER10 takes 10% off the subtotal
curl -X POST https://api.northwind-shop.com/v1/cart/8f61c2/promo \
  -H "Content-Type: application/json" \
  -d '{"code": "SUMMER10"}'
Pass

200 with discount_total reduced by 10% of the pre-discount subtotal; subtotal itself is unchanged.

Watch

A stale cart_total that doesn't recompute after the promo applies is the most common regression here — reload the cart and check the total actually changed, don't trust the promo response alone.

Step 2

Pay with a card that declines

Action

Submit payment with a Stripe test card that always triggers a decline.

// tok_chargeDeclined always triggers a hard decline in Stripe's test mode
const res = await fetch("/api/checkout/pay", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ cart_id: cartId, payment_token: "tok_chargeDeclined" })
});
const data = await res.json();
console.log(res.status === 402, data.decline_code);
Pass

402 with a decline_code (e.g. "generic_decline"); no order_id in the response.

Watch

A decline that still creates a row in the orders table — even unpaid — is a data-integrity bug worth flagging on its own; check the orders table directly, don't just trust this response.

Result
